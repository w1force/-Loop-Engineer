# API contract verification generator

Generate candidate-specific API tests and a machine-readable artifact manifest. This
Skill creates evidence inputs; it never declares a candidate verified and never releases
code. The Coordinator remains responsible for freezing generated bytes and replaying the
same artifacts against control and candidate.

## Required inputs

Require all of the following before generation:

- the IncidentBundle digest, failure signature, and matched rule;
- immutable control and candidate snapshot digests plus the candidate diff;
- a Coordinator-owned expected-bindings JSON file outside the generated output directory;
- the trusted canonical OpenAPI document and its digest;
- a Coordinator-owned output directory outside both application workspaces;
- an isolated non-production target contract, approved fixture capabilities, fixed seed,
  frozen clock, exact dependency versions, and command/time/network limits.

If any required input is missing or the specification uses unresolved remote references,
return BLOCKED with the missing requirement. Do not infer an oracle from candidate behavior.

## Load the focused guidance

Always read [references/generation-contract.md](references/generation-contract.md). It

handoff.

Read the vendored Drift material only when emitting Drift artifacts:

- [vendor/pactflow-drift/test-cases.md](vendor/pactflow-drift/test-cases.md) for targets,
  parameters, response assertions, datasets, and tags;

The vendored material is adapted from the source recorded in

generation-contract.md override upstream retry, mock, and coverage guidance.

## Workflow

1. Run scripts/inventory_openapi.py on the frozen specification. Treat every emitted
   response and category obligation as required until satisfied or explicitly blocked.
2. Map the incident and changed code to affected operations. Always include the exact
   incident regression. Add contract, boundary, state-transition, and idempotency cases
   required by the inventory and risk tags.
3. Generate tests, fixtures, hooks, and runner configuration only in the Coordinator-owned
   output directory. Never edit the application, canonical specification, control snapshot,
   or candidate snapshot.
4. Give every assertion an independent oracle source and digest. Generate deterministic
   setup and unconditional cleanup for every stateful test.
5. Produce artifact-manifest.json conforming to
   [references/artifact-manifest.schema.json](references/artifact-manifest.schema.json).
6. Run scripts/validate_artifact_manifest.py with the Coordinator-owned `--expected-bindings`
   file before handoff. A validation error or unresolved required obligation yields BLOCKED,
   never a partial success.
7. Return only the generated root, manifest path, status, and blocking reasons. The
   Coordinator snapshots the directory and decides whether execution may begin.

## Non-negotiable constraints

- Cover every documented explicit response, including 3xx and 5xx, plus wildcard and
  default responses. If a response cannot be triggered deterministically, record a blocking
  obligation; never silently exclude it.
- Do not weaken expected status, schema, body, headers, side effects, or the incident failure
  signature to make the candidate pass.
- Never use retry-until-pass, Drift --failed loops, probabilistic eventual-pass rules, current
  time, unseeded randomness, or mutable remote fixtures.
- Never send Prism Prefer: code headers to a live service. They are allowed only when the
  frozen target_kind is prism_mock; the validator rejects them elsewhere.
- Never target production, publish results, update remote Postman/PactFlow state, install
  dependencies globally, or fetch runtime dependencies during verification.
- Store secret names only. Do not write secret values into tests, fixtures, logs, or the
  manifest.
- A generated test is not evidence until its exact bytes, dependency/image digests, inputs,
  oracle, setup, cleanup, and command have been frozen and independently executed.
